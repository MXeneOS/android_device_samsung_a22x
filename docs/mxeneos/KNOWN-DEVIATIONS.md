## Can the two sepolicy conflicts be solved from the device tree instead?
- A variable opt-out: **no.** `build/make/core/config.mk` includes `device/lineage/sepolicy/common/sepolicy.mk` last, "to avoid accidental resetting by device configs", and only if `LINEAGE_BUILD` is set. The rules sit in `common/private`, which is always added to `SYSTEM_EXT_PRIVATE_SEPOLICY_DIRS`. Leaving `LINEAGE_BUILD` unset would drop all of Lineage's sepolicy (not acceptable).
- Soong override in the device tree: **plausible, unproven.** `system_ext_sepolicy.cil` (`system/sepolicy/Android.bp:331`) and `system_ext_property_contexts` (`system/sepolicy/contexts/Android.bp:246`) are ordinary modules. A device Android.bp could define a `genrule` that filters the generated file (sed away the three rules) and a `prebuilt_etc` with `overrides: [...]` and the same install path. Tracks upstream (filters generated output, no copy), a22x-only. Effort: about 1 to 3 hours (each Soong error costs a 14-minute analysis cycle).
- Port-level manifest override: `manifests/mxeneos_a22x.xml` replaces `device/lineage/sepolicy` with a fork that carries the two small commits. Low effort; the port owns the rebase.
- Upstream Lineage: ask to move those rules to files that only apply when the vendor policy is built from source.
